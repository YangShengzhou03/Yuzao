> 版本：2026-11-01 基线

## 0. 分析框架与验收口径

用户原始目标可拆为 4 条硬指标，任何路线都须据此验收：

| 编号 | 目标 | 验收方式 |
|---|---|---|
| G1 | 自然语言 → 原生特征树文件 | 生成的 `.prt/.asm` 打开后，模型树里能看到草图/拉伸/孔/圆角等**特征节点**（不是导入实体） |
| G2 | 画布拾取 → 自然语言改特征 | 点某个面/边 → 定位到具体特征 id → 改参数 → **只重算下游**，模型树结构不变 |
| G3 | 特征级修改，非重建 | 编辑后特征总数不减少、特征 id 不变，`Regenerate` 而非 `New` |
| G4 | 工程师原生可编辑 | 用原版 Creo 打开，能继续编辑特征参数/草图/装配约束，与人工 Creo 画图一致 |

**结论先行**：G4 直接排除所有非 Creo 内核路线。差异只发生在「用什么方式驱动本机 Creo」。因此本报告把 R1–R5（均驱动 Creo）作为主评估对象，R6（FreeCAD 内核）作为降级备胎，并单独评估「分层架构（Vue+Tauri+Rust+Creo+USD）」与「FeatureSpec IR / USD 视图桥」两个横切层的可行性。

## 3. 各路线逐维深析

### R2 — TOOLKIT（C，protk DLL 内嵌）★ 生产级主线

- **技术实现**：唯一能完整实现 G1–G4 的路线。C Toolkit 的 `ProFeatureCreate` / `ProSolidRegenerate` / `ProParamvalueSet` 暴露了 PTC 全部参数化能力，特征 id/参数/依赖关系可直接读写，G2、G3 天然成立。交付形态干净：客户已装 Creo + 一个 DLL + 一个 `protk.dat` 注册项。
- **优势**：能力天花板最高（圆角/阵列/扫描/装配约束全覆盖）、特征级最小重算确定性最强、解锁后终端用户无需开发授权（利于产品化）。
- **潜在障碍**：① `protk_unlock` 注册/解锁流程尚未验证；② 必须随 Creo 进程调试，迭代慢；③ 装配约束 API 在 pfc/C 中也偏薄，仍是难点；④ C 语言 API 心智负担重，排错依赖 PTC 文档与示例。
- **资源投入**：需 1 名资深 C/C++ + PTC TOOLKIT 工程师（市场稀缺、单价高）。
- **时间周期（指示性，非承诺）**：按 ROADMAP §5 的阶段口径，P1 3–5 周 + P2 3–5 周 + P3 5–7 周 → **P1–P3 约 11–17 周**到可演示；`protk_unlock` 与 DLL 注册探针 2–4 周与 P1–P3 并行。
- **成本预算（估算）**：主要为人力（稀缺专家），无第三方授权费；USD 工具链开源。若外采 TOOLKIT 人力按市场价，是六条路线中人力成本最高者。
- **关键依赖**：① 客户侧 Creo + Toolkit 合法授权（解锁后终端免开发授权）；② `protk_unlock` 流程跑通；③ PTC 官方示例与 GSG 文档可读。

### R1 — Object TOOLKIT（C++ pfc，异步 exe）★ 先导线 / MVP 最快路径

- **技术实现**：`spawn + Connect` 已实测打通（见 §1）。外部 exe 常驻、IPC 与 Rust/Tauri 分层最干净，与 R2 共用 pfc 语义，代码可迁移。
- **优势**：比 R2 调试友好（独立进程、可独立重启重放）；分层最解耦；已具备可编译工程（`probe_otk.exe`）。
- **潜在障碍**：① pfc 的"特征创建"面比 C Toolkit 窄——扫描、阵列变体、部分装配约束可能 pfc 覆盖不到，届时仍需 R2 补位；② `Start()` 已废，必须自管理 `parametric` 进程生命周期（已规避，但属于自建复杂度）。
- **资源投入**：1 名 C++/OTK 工程师，可得性优于 R2 的 C Toolkit 专家。
- **时间周期（指示性，非承诺）**：按 ROADMAP §5 的阶段口径，P1（FeatureSpec + 基础特征）3–5 周 + P2（视图桥 + 拾取回传）3–5 周 → **MVP 约 6–10 周**；再叠加 P3（装配/复杂特征）5–7 周 → 全量约 11–17 周。
- **成本预算（估算）**：人力低于 R2；无授权费。
- **关键依赖**：① 无界面 Creo 稳定拉起（已验证）；② pfc 特征创建覆盖度（待验证，是最大不确定性）；③ Rust↔exe 的 IPC 与特征 id 映射表。

### R3 — J-Link（Java pfc）

- **技术实现**：与 R1 同一套 pfc API，连接/建模逻辑可复刻。语言门槛低、示例多。
- **评估**：可作为 R1 的快速验证替代，但需 JRE 与类路径管理，部署体积与性能无优势，且 pfc 覆盖更窄。**不宜作为长期主线**，仅作资源受限时的验证跳板。

### R4 — Trail file（.txf）回放

- **技术实现**：录制 UI 操作重放，零开发授权。
- **致命缺陷**：回放依赖 UI 坐标系与选择序列，参数是"录进去的坐标/数字"而非参数化引用；"把圆角改成 R1.5"必须重新回放=重建（违反 G3）；任何界面差异都会失败。
- **结论**：只能做演示外壳，不能承载产品主线；**不建议投入主线资源**。

### R5 — Pro/PROGRAM + 关系式

- **技术实现**：在已有 `.prt` 内写关系式（`d1=100`）驱动尺寸再 `Regenerate`，完全参数化、G4 天然满足。
- **定位**：只能改**已存在特征的尺寸/关系**，不能从零建特征树（不满足 G1）。**作为 R1/R2 的"参数微调"补充**——改直径/偏移等纯参数动作优先走关系式，减少 API 调用、提高稳定性。

### R6 — FreeCAD + usd-brep（非 Creo 内核）

- **技术实现**：FreeCAD PartDesign 特征树 + recompute，产出 STEP/`.aicad.json`，经 `usd-brep` 写 BrepArray。G1/G2/G3 可近似，视图层已验证。
- **致命缺陷**：G4 不成立——产出不是原生 `.prt`，工程师在 Creo 里拿到的是导入实体（无特征树）。与用户 L19-22「原生 prt」硬要求本质冲突。
- **定位**：仅当客户**没有 Creo** 时降级备胎；不作为主路线。

## 4. 横切层与整体架构可行性

选定 Creo 内核后，无论走 R1 还是 R2，都必须自建两件东西，其可行性直接决定产品上限：

### 4.1 FeatureSpec IR（约束 LLM 输出，解决"AI 零幻觉"）

- **作用**：LLM 只输出受控 JSON（`features` 建、`edits` 改），后端映射为 Creo 调用；语义引用 `F002.face[top]` 由映射表维护，绝不让模型猜 face index。
- **可行性**：设计已成型、理念扎实；**当前未在代码中落地**，是 P1 的核心工程。风险点在于"语义拓扑引用"的维护成本（每次 Regenerate 后面/边命名稳定性）——这是 G2 能否成立的技术命门，需单独排障验证。

### 4.2 USD 视图桥（Creo → USD，承载画布拾取）

- **作用**：Creo 无 USD 导出，固定链路 `Creo(真值) → 导出 STEP/VRML/STL → 转 .usda(含 customData.featureId) → 前端渲染拾取`。
- **可行性**：B-Rep 写读/网格化已验证（0.002% 误差）。**待解决**：① STEP→USD 转换的保真度与性能（大模型/装配体）；② 特征 id 与 USD 面/边的精确对应（拾取定位准确性）；③ 是否用 BrepArray（精确但重）还是仅网格（拾取够用但丢失精确几何）——`ROADMAP.md` §7 近期行动 4 待 Owner 在 P2 前拍板。

### 4.3 分层架构（Vue + Tauri/Rust + Creo + USD）

- 前端空壳 ✅、USD 能力 ✅、Creo 内核通路 ✅，三层各自技术可行性高；**集成风险**集中在：Rust 调度层（LLM 编排、任务队列、Undo/Redo、特征 id 映射）是尚未动工的最大工程量，且需与不稳定 Creo 进程做好崩溃隔离与版本快照重放。

## 5. 风险因素汇总与缓解

### 5.1 技术风险
| 风险 | 影响 | 缓解 |
|---|---|---|
| pfc/C API 特征覆盖度不足（pfc 无特征创建 Instructions；圆角/阵列/扫描/装配约束需 C Toolkit） | 可能逼回 R2，推翻 R1 先导线假设 | P1.4 提前做"特征覆盖度探针"，先验证后承诺 |
| R2 `protk_unlock` 未跑通 | 生产级主线受阻 | 与 R1 并行启动 R2 探针；unlock 失败即评估外购/咨询 PTC |
| 无界面 Creo 长稳性（内存/崩溃） | 桌面端体验崩坏 | 进程独立 + 版本快照重放 + 自动重启 |
| STEP→USD 保真/性能 | 画布拾取不准、大装配卡顿 | 先做网格方案验证拾取，再决定是否上 BrepArray |
| 语义拓扑命名稳定性 | G2 拾取漂移 | FeatureSpec 映射表 + Regenerate 后重映射校验 |

### 5.2 法律/合规风险（最高优先级）
- **当前 Creo/Toolkit 授权为第三方打包（`PTC_D_SSQ`）**。技术验证可用，但**正式发布必须每台机器由客户自身合法持有 Creo + Toolkit 授权**；本产品仅作"运行在客户已授权 Creo 之上的伴侣程序"，不分发 Creo 本体。
- 这是**商业可行性的前置条件**，必须在对外发布前与 Owner 确认授权归属与合规口径，否则有下架/法务风险。

### 5.3 产品/市场风险
- 竞品中望已发布 AI Copilot + 自主内核 + 信创（麒麟/鸿蒙/统信），"靠 AI 就能赢"不成立。差异化必须落在**自然语言→参数化特征树→可回溯编辑的闭环**与 **USD 协作数据模型**，而非"AI 帮点按钮"。
- 战略文档定义的 T0（DWG 双向兼容/2D 绘制/动态块/标注/打印）是"入场生死线"，但当前内核路线只覆盖 T2/T3（3D 参数化/AI），**2D/DWG 缺口巨大**，若市场窗口要求尽快进入，需提前规划 ODA 授权（有预算门禁）与 2D 模块，否则只能切"3D 参数化细分赛道"。

### 5.4 程序/治理风险
- **已补齐**：`ROADMAP.md`（统一 P0–P6 排期）与 `docs/adr/ADR-009~012` 已在本次结构重建中实体化，README 与战略文档的阶段口径得以统一。
- **已解决**：战略文档对排期/阶段的引用统一为 `ROADMAP.md`（原 `PHASES.md` 悬空引用已改），无悬空链接。
- 影响（历史）：此前时间/资源无单一基线、跨文档结论可能冲突；补齐后已缓解。

## 6. 资源 / 成本 / 周期量级估算（合计视角）

> 下列为**指示性估算**，非承诺；实际以 `ROADMAP.md` §5 为准（P4–P6 资源/周期亦见该节，口径一致）。人力按"资深工程师当量（FTE）"计。

| 阶段 | 内容 | 路线 | 人力 | 周期估算 |
|---|---|---|---|---|
| P0（已完成） | 无界面 Creo 建零件落盘 | R1 通路 | 0.5 FTE × 数日 | 已完成 ✅ |
| P1 | FeatureSpec IR + 草图/拉伸/孔 | R1/R2 | 1 FTE（C++/OTK 或 C/Toolkit） | 3–5 周 |
| P2 | USD 视图桥 + 特征 id 注入 + 拾取回传 | 横切 | 1 FTE（Rust+前端） | 3–5 周 |
| P3 | 装配/圆角/阵列/Undo/多轮上下文 | R1→R2 | 1–1.5 FTE | 5–7 周 |
| R2 并行探针 | protk_unlock + DLL 注册 + 全量 API | R2 | 0.5 FTE（稀缺专家） | 2–4 周（与 P1–P3 并行） |

- **总成本构成**：人力（主导，R2 专家最贵） + LLM 推理（若走本地大模型则一次性显卡投入，若走 API 则按量） + 极小额 USD/开源工具链。**无 Creo/PTC 授权费（客户侧承担）**，但 ODA（DWG）若要做 T0 入场线是独立预算门禁。
- **最小可行路径（MVP）**：R1 先导线 + P1–P2，按 ROADMAP §5 的 P1（3–5 周）+ P2（3–5 周）合计约 **6–10 周 / 1–1.5 FTE**，可跑通"自然语言生成带特征树 prt + 画布拾取改参"闭环演示。

## 7. 可行性结论与推荐建议

### 7.1 逐路线可行性结论

| 路线 | 可行性结论 |
|---|---|
| **R2 Toolkit DLL** | **高（理论）但待验证**：能力最全、是生产级答案；unlock 与全量 API 尚未跑通，属"高价值、中高风险、需尽快验证" |
| **R1 OTK 异步** | **高（已部分验证）**：spawn+Connect 通路实测通过，是最快出 MVP 的路线；最大不确定性是 pfc 特征覆盖度 |

| **R6 FreeCAD** | 低（对 G4）：仅无 Creo 客户的降级备胎 |

### 7.2 推荐路线组合（优先级排序）

1. **主线（生产级）— R2 Toolkit DLL**：目标终态，能力天花板最高、最契合 G1–G4。
2. **先导（MVP 最快）— R1 OTK 异步（spawn+Connect）**：立即推进，用最短时间验证商业闭环与 FeatureSpec/USD 横切层；其代码与 R2 同 pfc 语义可迁移。
3. **补充 — R5 Pro/PROGRAM + 关系式**：参数微调场景优先走关系式，降低 API 调用风险、提升稳定性。
4. **降级 — R6 FreeCAD**：仅当目标客户无 Creo 时启用，且需向客户明确"产出非原生 prt"。
5. **放弃 — R4 作产品主线、R3 作长期主线**：保留 R4 仅做售前演示外壳。

### 7.3 关键行动建议（按优先级）

1. **立即并行启动 R2 探针**：验证 `protk_unlock` 与 DLL 加载；若 2–4 周内不通，则 R1 升级为事实主线，R2 降级为"能力补位"。

### 7.4 总体可行性判断

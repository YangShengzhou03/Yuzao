# 文档同步规则（跨文档一致性映射）

> 目的：从机制上避免多文档之间的表述冲突。任何文档修改前，先查本表确定
> 「该事实的唯一权威来源」；修改权威来源后，按本表同步所有引用方。
>
> **权威关系**：[`ROADMAP.md`](../ROADMAP.md) 是目标、阶段、路线角色、任务、里程碑、
> 资源配置与验收标准的**唯一权威（SSOT）**。本文件只定义「事实 → 权威 → 引用方」的映射、
> 变更传播流程与审核清单，**不得在本文件内重新定义任何业务事实**。

---

## 1. 事实 → 唯一权威来源映射

| 事实类别 | 唯一权威 | 允许引用方式 | 禁止行为 |
|---|---|---|---|
| 目标定位与验收口径（G1–G4） | `ROADMAP.md` §0 | 「ROADMAP G1–G4」+ 原文照录 | 改写目标口径或另立编号 |
| 阶段定义与状态（P0–P6） | `ROADMAP.md` §2 | 「见 ROADMAP §2」+ 简述 | 在其他文档自定义阶段或状态 |
| 执行任务编号（`P{n}.{k}`） | `ROADMAP.md` §3 | 直接引用编号（如 `ROADMAP P4.4`） | 新增/改写任务编号；用 `T*.x` 指代执行任务 |
| 路线角色（R1–R6） | `docs/adr/ADR-010.md` | 「见 ADR-010」 | 口头另定「主线」或互换角色 |
| 路线当前状态（R1–R6） | `ROADMAP.md` §1 | 引用状态列 | 在其他文档另写一套路线状态 |
| 里程碑（M0–M6） | `ROADMAP.md` §6 | 直接引用 M 编号 | 自造 M7 等未定义里程碑 |
| 资源配置 / 排期 / 工期 | `ROADMAP.md` §5 | 引用并标注「指示性、非承诺」 | 另写一套排期数字或独立估算 |
| 验收标准（阶段级） | `ROADMAP.md` §2 | 引用阶段验收列 | 在其他文档重定义验收 |
| 市场功能层级（T0–T4） | `docs/竞品对标与功能规划.md` §3 | 引用「市场层级 T0–T4」 | 与 ROADMAP 阶段/任务编号混用；市场优先级另用 P0–P3 命名 |
| 架构分层 / 数据流 / FeatureSpec | `docs/ARCHITECTURE.md` §1–§6 | 引用章节号 | 在战略文档重复定义架构细节 |
| 验证状态（✅/🔧/❌） | `CHANGELOG.md`（按时间）+ `docs/ARCHITECTURE.md` §8（按现状） | 双源引用 | 在其他文档写「已验证」而 CHANGELOG 无记录 |
| 实测数据（文件大小、误差、版本号） | `CHANGELOG.md` 对应条目 | 引用条目 | 凭记忆改写数字 |
| 合规口径 | `docs/adr/ADR-009.md` + `README.md` §合规 | 「客户自持 Creo/Toolkit 授权，本产品为伴侣程序」 | 宣称分发 Creo 本体或免授权使用 |
| 仓库目录结构 | `README.md` §仓库结构 | 引用目录树 | 在其他文档维护另一份目录树 |

## 2. 编号命名空间（禁止混用）

| 命名空间 | 含义 | 权威定义 | 示例 |
|---|---|---|---|
| `G1–G4` | 产品验收硬指标 | ROADMAP §0 | `G2` = 画布拾取 → 改特征 |
| `P0–P6` | 执行阶段 | ROADMAP §2 | `P2` = 视图导出 + 拾取回传 |
| `P{n}.{k}` | 执行任务 | ROADMAP §3 | `P4.4` = DWG 双向兼容 |
| `R1–R6` | 内核驱动路线 | ADR-010（角色）+ ROADMAP §1（状态） | `R2` = Toolkit DLL 主线 |
| `T0–T4` | 市场功能层级（非执行任务） | 竞品文档 §3 | `T0` = 入场生死线 |
| `M0–M6` | 里程碑 | ROADMAP §6 | `M4` = R2 `protk_unlock` 通过 |
| `Phase N` | **已废止**的历史阶段编号 | 仅竞品文档 §5 映射表 / CHANGELOG 历史条目 | 只允许作为「旧 → 新」映射出现 |

> 附加约定：竞品文档的「市场优先级」一律写成「市场优先级 1/2/3/4」，
> **不得**写成「市场 P0/P1…」，避免与执行阶段 `P0–P6` 混淆。

## 3. 状态标记统一口径

| 对象 | 允许的标记 | 说明 |
|---|---|---|
| 阶段 / 任务 | ✅ 已通过 / 🔧 进行中 / 未开始 / 未排期 / 待定 | 「未开始」不再写作「待开始」；「未排期」用于受外部门禁阻塞项 |
| 路线状态 | ✅ P0 / P1 探针 / 未启 | 路线状态不直接沿用阶段词 |
| 验证结论 | ✅ 已验证 / 🔧 验证中 / ❌ 未通过或未验证 | 禁止使用 🔄、⚠️已通过 等混用写法 |

## 4. 引用规则

1. **只允许引用真实存在的文件与章节**。写引用前确认目标文件在仓库中；
   删除/重命名文件时，同一次提交内必须更新全部引用（`Grep` 旧文件名核实为 0 命中）。
2. 引用格式统一为「文件 §章节名」或「ROADMAP §n / ROADMAP P{n}.{k}」。
3. 数字只允许「照录权威来源」或「由权威数字直接推导并注明推导式」，不得另行估值。
4. 历史文档（CHANGELOG、工作日志）中已废止的编号必须保留「已废止/已被替代」标注，
   不得作为现行排期或验收依据。
5. 同一事实在多个文档出现时，表述必须逐字一致（目标表、阶段表、路线定位句、资源表）。

## 5. 变更同步流程（每次改动按此自查）

1. 确定改动涉及 §1 映射表中的哪一类事实；
2. 修改**唯一权威来源**文档；
3. 按映射表 `Grep` 引用方，关键词至少覆盖：
   `G1–G4`、`P0–P6`、`P{n}.{k}`、`R1–R6`、`T0–T4`、`M0–M6`、`Phase`、
   `✅`/`🔧`/`❌`、`已验证`/`未验证`、`周`/`FTE`、`主线`/`先导`/`降级`；
4. 逐个更新引用方，保持口径与数字一致；
5. 运行自动校验：`python tools/docs/consistency_check.py`，必须 0 error；
6. 提交信息注明影响范围（如 `docs: 同步 P1 状态至 README/ROADMAP/native`）。

> 阶段 / 排期 / 验收标准 / 路线定位的变更，还须走 `ROADMAP.md` §9 变更评审。
